04Architecture

Public entry. Private execution.

One browser origin, two CloudFront paths, and explicit boundaries between edge, application, and data.

01 / OAC

Same-origin, private assets

CloudFront keeps browser requests same-origin. Session cookies and CSRF remain part of Django’s authentication flow.

02 / VPC

Private access has a cost

Required AWS paths were validated before removing NAT. Interface endpoint hourly costs still matter at this small scale.

03 / HA

A foundation, with limits

Two-AZ networking does not make one task and Single-AZ RDS highly available. Multi-replica capacity and recovery tests remain future work.

05Engineering challenges

The interesting work happens at the edges.

Three documented incidents where observation changed the next decision.

01PHASE KPermissions that passed static review

Problem

CI and OIDC succeeded, but the first image delivery attempt failed.

Diagnosis

Runtime exposed a missing repository-scoped ecr:BatchGetImage permission. Static policy validation had not proven deployment completeness.

Decision & result

Added only the missing repository permission. The rerun reused the existing immutable SHA image and completed the ECS rollout.

↳Static analysis and runtime validation are complementary.

02PHASE MMore workers, worse performance

Problem

Would a second synchronous Gunicorn worker improve the small Fargate task?

Diagnosis

On the unchanged 0.25-vCPU task, two workers drove CPU to approximately 100% and operational p95 to approximately 5.66 seconds.

Decision & result

Rejected the experiment and restored one worker. More CPU and/or replicas need measurement before increasing concurrency.

↳Concurrency has to fit the available CPU budget.

03PHASE LSensitive inputs, visible plan output

Problem

A sensitive OIDC input appeared in the derived IAM trust-policy plan output.

Diagnosis

Sensitivity did not propagate to the final policy expression. Marking an input sensitive alone was insufficient.

Decision & result

Marked the final expression sensitive and verified semantic equivalence and no-op convergence. Kept remote state private and encrypted.

↳Display masking does not remove sensitive data from state.

Authenticated, read-heavy workload

k6 retained Django sessions with one login per virtual user and realistic think time. Operational latency excludes CSRF bootstrap and login. The target was p95 < 1.5 seconds on a 0.25-vCPU / 512-MiB task.

A virtual user is not a tenant or a registered-user capacity claim. At 20 and 25 VUs, the application stayed functional while the latency target was missed.

IMPLEMENTED

A controlled delivery foundation

Private ECS/RDS, S3/OAC, CI with ephemeral PostgreSQL, OIDC, immutable SHA images, migration-gated rollout, logs, alarms, and selected Terraform imports.

VALIDATED

Positive and negative runtime evidence

Django tests and checks, successful migrations, removed/restored network access, S3 denial, session/CSRF behavior, denied unrelated IAM operations, ECS rollout, and Terraform no-op convergence.

DOCUMENTED

Costs, recovery, and ownership

Cost analysis separated gross usage from credits. Backup & Restore, provisional recovery objectives, and IaC ownership boundaries were documented; full-account Terraform ownership was never claimed.

DEFERRED / FUTURE WORK

Production requires more validation

Multi-task HA, RDS Multi-AZ, tested restore and measured RTO, WAF enforcement and tuning, secret rotation, production SLOs, frontend release automation, and stronger supply-chain attestations.

Evidence basis: Phase N portfolio closure and the recorded Phase K, L, and M findings. Operational logs, account data, and internal configuration remain private. WAF Count is monitoring, not blocking; backup availability is not a tested restore.
